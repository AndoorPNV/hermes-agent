# 01 · Спецификация HermesUI

Версия: 1.0 · Дата: 2026-10-30 · Статус: baseline
Целевая платформа: Hermes Agent **v0.22.5 (2026.9.24)**, git-install, Windows 11, `$HERMES_HOME = C:\Users\mrkee\AppData\Local\hermes`

---

## 1. Контекст

Hermes Agent расширяется пятью независимыми механизмами (скиллы, Python-плагины,
desktop-плагины, скины/i18n, MCP) и одним файлом конфигурации на 31 корневой раздел.
Каждый механизм живёт в своей папке внутри `$HERMES_HOME`, размножается по профилям и
**никак не версионируется**: обновление Hermes не ломает расширения сразу, но и не
сохраняет их состояние; переустановка машины/профиля означает ручную сборку заново.

Проблема, которую решает проект: **адаптация Hermes сегодня — это набор ручных действий
в `$HERMES_HOME`, который невозможно воспроизвести, откатить и передать.**

## 2. Продукт

HermesUI — **дистрибутив-надстройка над стоковым Hermes**: git-репозиторий с
декларациями модулей + установщик, который приводит `$HERMES_HOME` к объявленному
состоянию, ничего не форкая в upstream.

Три свойства, которые определяют продукт:

1. **Декларативность.** Состояние машины описывается `modules/*/module.yaml`, а не
   действиями в UI.
2. **Обратимость.** Каждое применение пишет запись в `hermesui.db` (`applied_changes`,
   `audit_log`) и имеет обратную операцию (`hermesui rollback <change-id>`).
3. **Совместимость.** Апгрейд Hermes не требует правок наших модулей; расхождение
   версии/схемы обнаруживается на `hermesui doctor`, а не в рантайме.

## 3. Цели и не-цели

### Цели (G)

| ID | Цель | Проверяемый признак |
|---|---|---|
| G1 | Воспроизводимая установка набора расширений | `hermesui apply` на чистом профиле даёт идентичный набор скиллов/плагинов/скина |
| G2 | Изменение интерфейса без правки кода приложения | Тема + desktop-плагин + языковой пакет ставятся как модули и откатываются |
| G3 | Долгосрочная память проекта | vault наполнен и связан, MOC ведёт ко всем темам |
| G4 | Безопасные границы | ни один модуль не получает capability без согласия пользователя |
| G5 | Наблюдаемость | любое изменение состояния видно в `audit_log` с id модуля и ревизией |

### Не-цели (NG)

- NG1 Форк/патч ядра Hermes как способ доставки фич (патч — только исключение + ADR).
- NG2 Свой чат-клиент, свой агентный цикл, свой LLM-роутинг.
- NG3 Мультитенантность, серверный деплой на много пользователей.
- NG4 Замена Obsidian приложением (vault — файлы, не сервис).
- NG5 Синхронизация между машинами (только git + `hermesui export`).

## 5. Функциональные требования

### FR-1 · Каталог модулей
Система ведёт каталог модулей четырёх типов: `skill`, `plugin` (Python),
`ui` (desktop-плагин), `theme` (+ `i18n` как подтип `theme`).
Каждый модуль: `id`, `version`, `type`, `provides`, `requires`, `capabilities`, `artifacts`.
**Приёмка:** `hermesui list` печатает все модули с типом/версией/статусом; id уникален,
совпадает с именем папки.

### FR-2 · Планирование (plan)
`hermesui plan` вычисляет diff между объявленным и фактическим состоянием без записи:
что установить, что обновить, что удалить, какие конфликты id обнаружены.
**Приёмка:** на чистом профиле план перечисляет все модули; повторный `plan` после
`apply` — пуст; конфликт двух модулей с одним id — ошибка плана, а не частичное применение.

### FR-3 · Применение (apply)
`hermesui apply [--only id]` копирует/устанавливает артефакты, включает плагины через
`plugins.enabled`, применяет скин, пишет `applied_changes` + `audit_log`.
**Приёмка:** каждая запись `applied_changes` имеет `before_json`/`after_json` и хэш
артефакта; `apply` идемпотентен (второй запуск не создаёт изменений).

### FR-4 · Откат
`hermesui rollback <change-id|--last N>` восстанавливает предыдущее состояние файлов и
ключей конфига из бэкапа.
**Приёмка:** после `rollback` `plan` показывает ровно то, что было до `apply`.

### FR-5 · Проверка (doctor)
Диагностика: совместимость версии Hermes со `schema_version` (ожидается 32), наличие
папок, дубликаты id между `plugins/` и `desktop-plugins/`, смонтированность REST-бэкендов,
валидность `module.yaml`, доступность vault, размер `message`-индексов.
**Приёмка:** каждая проверка возвращает `ok|warn|fail` + конкретную команду исправления.

### FR-6 · Скиллы как модуль
Скилл — папка с `SKILL.md` (frontmatter: `name`, `description`, `version`, `author`,
`license`, `platforms`, `metadata.hermes.tags`) и необязательными
`references/`, `templates/`, `scripts/`, `assets/`.
**Приёмка:** `skill_view(name)` открывает скилл; описание в первой строке —
самодостаточный триггер «Use when …»; скилл не дублирует содержимое `docs/`.

### FR-7 · Desktop-UI модуль
Файл `plugin.js` (plain ESM, без сборки) с `export default { id, name, register(ctx) }`,
подключающий не более одного *основного* места (page `ROUTES_AREA` **или** pane
`'panes'`, не оба).
**Приёмка:** после сохранения файла плагин загружается hot-reload без рестарта;
⌘K → «Reload desktop plugins» — резервный путь; ошибка загрузки видна тостом.

### FR-8 · Тема и язык
Тема — скин (`skins/<name>.yaml`) + `display.skin`; языковой пакет — модуль
`ctx.i18n.registerAppLocale(code, {…})` в desktop-плагине либо `locales/*.desktop.yaml`.
**Приёмка:** смена темы видна на CLI/TUI/desktop в пределах ~1 с; ни один компонент
модуля не содержит hex-цветов (только `var(--ui-*)`, `var(--theme-*)`).

### FR-9 · Python-плагин с бэкендом
Единый пакет `plugins/<id>/`: `plugin.yaml`, `__init__.py` c `register(ctx)`,
`dashboard/manifest.json`, `dashboard/plugin_api.py` (module-level `router = APIRouter()`),
опционально `desktop/plugin.js`.
**Приёмка:** `curl` на `/api/plugins/<id>/…` даёт **401** (смонтирован); хуки
`pre_tool_call` / `post_tool_call` / `transform_tool_result` / `on_session_end`
срабатывают; блокирующий хук работает только после выдачи `tools.override` пользователем.

### FR-10 · Vault
Проект ведёт vault `F:\06_AI\HermesUI\Obsidian\HermesUI`: MOC + заметки
`Архитектура`, `Модули`, `Интеграции`, `Данные и БД`, `Решения (ADR)`; frontmatter
`tags/updated/status`; связи вики-ссылками.
**Приёмка:** из MOC достижима любая заметка за 1 клик; ни одна заметка не содержит
секретов и не копирует DDL.

### FR-11 · Аудит и журнал
Любая операция записи — строка в `audit_log` (кто: `user|agent|installer`, что, какой
модуль, ревизия, результат).
**Приёмка:** `hermesui log --last 20` показывает историю; удаление строк невозможно
(append-only через триггер).

### FR-12 · Совместимость при апгрейде
`hermesui doctor` сравнивает `hermes --version` и `state.db.schema_version` с
зафиксированными в `hermesui.db.settings`; расхождение — `warn` с чек-листом.
**Приёмка:** подмена ожидаемой версии в настройках даёт `warn`, а не падение.

## 6. Нефункциональные требования

| ID | Требование | Значение |
|---|---|---|
| NFR-1 | Время `plan` на 20 модулях | < 2 с |
| NFR-2 | Время `apply` одного UI-модуля | < 3 с (hot-reload не ждём) |
| NFR-3 | Отсутствие простоя | `apply` не перезапускает гейтвей; рестарт — отдельное действие пользователя |
| NFR-4 | Целостность | бэкап артефакта до перезаписи; откат без потери файлов |
| NFR-5 | Безопасность | 0 секретов в git и vault; capabilities — только с согласия |
| NFR-6 | Переносимость | пути только через `$HERMES_HOME` / `get_hermes_home()`; Windows + Linux |
| NFR-7 | Читаемость | документация на русском, идентификаторы английские |
| NFR-8 | Наблюдаемость | каждый модуль умеет сказать, что он не работает (`backend unavailable [<err>]`) |

## 7. Ограничения

1. Плагин-бэкенд инертен до рестарта гейтвея — архитектурное свойство, не баг.
2. `state.db` — **чужой** контракт: пишем только документированные операции (см. `03-DATABASE.md`).
3. Desktop-плагин не имеет доступа к ФС; запись — только через Python-бэкенд (`ctx.rest`).
4. JSX в `plugin.js` не компилируется — только `jsx()`/`jsxs()` из `react/jsx-runtime`.
5. `plugin.js` без `ResizeObserver` на canvas ломается при ресайзе панели.
6. Один id на оба половины плагина; коллизия = исчезновение UI без ошибки.
7. Windows: PTY, пути и `\r` — см. `references/windows-quirks.md` скилла `hermes-agent`.

## 8. Метрики успеха

| Метрика | Цель | Как мерим |
|---|---|---|
| Воспроизводимость | 100% модулей восстанавливаются на чистом профиле | `apply` → `doctor` → все `ok` |
| Доля ручных правок `$HERMES_HOME` вне installer | 0 | `git status` в `$HERMES_HOME` пуст (где применимо) + `audit_log` |
| Покрытие документацией | каждый модуль имеет строку в `docs/05-MODULES.md` и заметку-ссылку | ревью чек-листа |
| Откаты | 100% `apply` откатываются без остатка | тест: `apply` → `rollback` → `plan` пуст |
| Актуальность vault | расхождение с `docs/` < 14 дней | cron-сверка |

## 9. Риски

| Риск | Влияние | Митигация |
|---|---|---|
| Апгрейд Hermes меняет схему `state.db` | наши запросы падают | версия в `settings`, `doctor` блокирует `apply` при мажорном расхождении |
| Коллизия id плагинов | пропадает весь UI-модуль | проверка в `plan` + правило «один id» |
| Перезапись `config.yaml` при сбое | ломается гейтвей | только через `hermes config set`, бэкап перед записью |
| Vault расходится с `docs/` | неверные решения через месяц | ADR + еженедельная сверка |
| Desktop-плагин ломает layout | «интерфейс исчез» | сохранять layout перед экспериментами, откат модуля |
| Секрет в заметке | утечка | ревью + `hermesui doctor --secrets` |

## 10. Глоссарий

- **Модуль** — единица поставки (skill/plugin/ui/theme/i18n) с манифестом.
- **Half** — одна из половин плагина: `desktop/plugin.js` (UI) или `__init__.py`+`plugin_api.py` (бэкенд).
- **Capability** — объявленное и выданное пользователем право (`tools.override`, `llm.*`, `gateway.platform_actions`).
- **Скин** — YAML-палитра (`$HERMES_HOME/skins/<name>.yaml`), применяемая через `display.skin`.
- **Vault** — папка Obsidian-заметок проекта.
- **Plan/Apply/Rollback** — три фазы установщика.
