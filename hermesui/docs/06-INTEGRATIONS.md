### 1.3 Шаблон заметки

```markdown
---
tags: [hermesui/<тема>]
updated: 2026-10-30
status: active
---

# <Название>

<Одно предложение: зачем эта заметка существует.>

## Суть
<3–7 пунктов, связки «почему», а не пересказ docs.>

## Связи
- [[Другая заметка]] — почему связана
- `docs/05-MODULES.md` — точный контракт

## Открытые вопросы
- [ ] <что неизвестно и кто/когда решит>
```

### 1.4 Синхронизация (cron, ежедневно 09:00)

```
1. прочитать список docs/*.md + sha256
2. сравнить с vault_notes.doc_hash
3. для расхождений: обновить соответствующий раздел заметки, НЕ перезаписывая
   «Суть» и «Открытые вопросы» (это добавленная ценность vault)
4. записать новый doc_hash, synced_at
5. если заметка и docs противоречат по факту (версия, число роутов) — задача в kanban
   с приоритетом high, а не молчаливая правка
```

Ограничение: автоматика **не создаёт** новых заметок — новая тема появляется вручную
(иначе vault превращается в свалку автогенерации).

### 1.5 Чек-лист целостности vault

- [ ] Из MOC достижима любая заметка за 1 переход.
- [ ] У каждой заметки есть `tags`, `updated`, `status`.
- [ ] Нет секретов: `grep -riE "sk-|api[_-]?key|token|password" Obsidian/` → пусто.
- [ ] Нет DDL/полных JSON-схем (только ссылки на `db/schema.sql`).
- [ ] `updated:` не старше 14 дней при изменённом источнике.
- [ ] Заметки `deprecated` ссылаются на замену.

## 2. Модель памяти: что куда

Четыре разных хранилища, их нельзя путать — иначе знание дублируется и гниёт.

| Хранилище | Что там | Кто пишет | Загрузка |
|---|---|---|---|
| `memory` (Hermes, `memories/`) | факты, действующие в **каждой** сессии (пути, привычки, ограничения среды) | инструмент `memory` | всегда в контексте, жёсткий бюджет |
| **Skill** (`SKILL.md`) | процедуры и грабли для **типа задач** | `skill_manage` | по триггеру описания |
| **Vault** | связи, контекст, «почему», статусы проекта | Hermes/пользователь | вручную/Obsidian |
| `docs/` | контракты: DDL, роуты, форматы | git | по требованию |

Правило выбора: процедура → скилл; факт о пользователе/среде → memory; «почему так
решили» → vault ADR; «как устроено точно» → `docs/`.

## 4. MCP-серверы

- Добавление: `hermes mcp add` или `POST /api/mcp/catalog/install`.
- Область действия: профиль целиком (`config.yaml: mcp_servers`), не сессия.
- Инструменты видны как `mcp__<server>__<tool>` — на этом строится политика в `guards`.
- Каталог: `$HERMES_HOME/hermes-agent/plugin-catalog/*.yaml` (сотни записей) +
  `optional-mcps/`.

## 5. Cron и kanban

| Задача | Расписание | Действие | Куда пишет |
|---|---|---|---|
| `vault-sync` | `0 9 * * *` | сверка docs ↔ vault | `vault_notes`, kanban при конфликте |
| `doctor-weekly` | `0 10 * * 1` | полный `doctor` | `doctor_runs`, отчёт в чат |
| `backup-rotate` | `0 3 * * *` | чистка бэкапов по ретенции | `applied_changes`, FS |

Cron-сессии не появляются в графе проектов (`projects.tree` жёстко
`include_children=False` и исключает `source='cron'`) — это ожидаемо, не баг.

## 6. Внешние источники истины

| Источник | Зачем | Как |
|---|---|---|
| `https://hermes-agent.nousresearch.com/docs/llms.txt` | индекс всех возможностей платформы | `web_extract`; первый шаг при любом «а можно ли в Hermes X?» |
| `https://hermes-agent.nousresearch.com/docs/llms-full.txt` | весь доксет одним файлом | когда нужен контекст, а не ссылка |
| GitHub `NousResearch/hermes-agent` | исходники, changelog | при расхождении поведения |
| локальный `hermes-agent/` | установленная версия (v0.22.5) | **приоритет** над вебом при конфликте |
| `plugin-catalog/` | готовые плагины/MCP | кандидаты для заимствования, не для форка |

Правило: **локальная установка важнее документации в сети.** Если docs и код
расходятся — прав код; расхождение фиксируется в ADR.

## 7. Чек-лист интеграции (для нового модуля)

- [ ] Модуль не требует сети, кроме явно объявленных внешних вызовов.
- [ ] Секреты — только `.env`, имя переменной задокументировано.
- [ ] Пути — через `$HERMES_HOME` / `OBSIDIAN_VAULT_PATH`, без абсолютных в манифесте.
- [ ] Ошибка внешней системы видна пользователю (не проглатывается).
- [ ] Отказ внешней системы не блокирует чат (graceful degradation).
- [ ] Есть строка в `docs/05-MODULES.md` и в `[[Модули]]`.
