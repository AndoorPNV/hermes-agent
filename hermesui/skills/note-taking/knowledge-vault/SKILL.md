# Knowledge Vault

Vault как **долгосрочная память проекта для AI**, а не блокнот. Три слоя памяти,
структура `atlas/knowledge/sessions`, правило именования утверждениями и ритуал
«сохрани сессию». Всё это делает новую сессию дешёвой: контекст читается из файлов,
а не пересказывается заново.

## When to Use

- Пользователь просит «сделать второй мозг / память для проекта / подключить Obsidian» —
  к действующему проекту или к новому.
- Начало и конец рабочей сессии в проекте, у которого vault уже есть.
- Vault разрастается: заметки называются категориями (`auth.md`, `bugs.md`), `index.md`
  стал свалкой, ссылки не разрешаются.

Не использовать для: личных заметок и дневников (это `obsidian`); первичного каркаса
проекта `docs/`+`db/` (это `project-start` — вызывает этот скилл для vault-части).

## Модель: три слоя памяти

| Слой | Что | Объём | Кто пишет |
|---|---|---|---|
| `CLAUDE.md` / `HERMES.md` / `.cursorrules` | правила, стек, архитектура, **инструкция про vault** | 1–2 страницы | человек |
| Obsidian vault | граф знаний: решения, баги, паттерны, бизнес, история | старт 15–20 заметок, +2–5 за сессию | AI + человек |
| Memory (`~/.claude/projects/.../memory/`, `memories/`) | предпочтения и коррективы | мелко | AI сам |

Границы жёсткие: контракты (DDL, роуты, поля) — в репозитории; «почему так» и связи — в vault;
предпочтения пользователя — в memory. Дублирование = две правды, которые разойдутся за неделю.

## Стандарт структуры

```
my-project-vault/
├── 00-home/
│   ├── index.md                  # карта всех заметок, ≤100 строк
│   └── текущие приоритеты.md     # что сейчас в работе
├── atlas/                        # меняется редко
│   ├── архитектура проекта.md
│   ├── база данных.md
│   └── деплой.md
├── knowledge/
│   ├── integrations/             # по одной заметке на интеграцию/API
│   ├── decisions/                # решения + ПОЧЕМУ (ADR-формат)
│   ├── debugging/                # баг → симптом → причина → фикс
│   ├── patterns/                 # «все API routes валидируют через Zod»
│   └── business/                 # продукт, тарифы, аудитория, воронка
├── sessions/                     # лог на сессию, YYYY-MM-DD-<тема>.md
└── inbox/                        # необработанное, разбирается раз в неделю
```

Если в проекте уже есть свой vault-стандарт (например MOC `00 <Проект> (MOC).md` из
`project-start`) — **не переписывай его**: добавь недостающие папки (`sessions/`, `inbox/`,
`knowledge/patterns/`) и правило именования. Два конкурирующих оглавления хуже одного.

## Если Obsidian не установлен (и это нормально)

Vault — это **просто папка с `.md`**. `--vault <путь>` создаёт файлы в любом каталоге,
`.obsidian/` не нужен и не проверяется. Ни один шаг ниже не требует приложения:

| Работает без Obsidian | Появляется только с приложением |
|---|---|
| `read_file`/`search_files` по заметкам, frontmatter, `[[ ]]` как обычный текст | клик по ссылке, панель backlinks, авто-переименование ссылок |
| навигация по `index.md` + ссылкам (AI читает их как текст) | Graph View (Ctrl+G) — человеку, не AI |
| `scripts/vault_check.py` (резолвит ссылки по именам файлов) | плагины/Dataview/мобильный доступ |

Поэтому отдельный скилл «без Obsidian» не нужен — нужен только выбор места:

- **Отдельная папка** (по умолчанию): `<project>/Obsidian/<Имя>` или вне репозитория;
  путь в `OBSIDIAN_VAULT_PATH`.
- **Внутри репозитория**: `docs/knowledge/` — когда нужен версионированный граф вместе
  с кодом и не хочется второго корня. Тогда `docs/` остаётся контрактами, а
  `docs/knowledge/` — «почему» и связи; правило разделения не меняется.
- **Совсем без файлов**: не делать vault. Тогда знание живёт в `docs/` + memory и
  теряется при смене сессии — это осознанная цена, а не дефолт.

Предложи приложение только если пользователю нужен граф или он сам просит: установка —
5 минут, но vault ценен и без неё.

## Правило именования — главное

Имя заметки = **утверждение**, не категория. AI видит имена до открытия файла; категория
не сообщает ничего, утверждение сразу отвечает «релевантно или нет».

| ❌ Плохо | ✅ Хорошо |
|---|---|
| `auth.md` | `авторизация через Supabase Auth с RLS на каждой таблице.md` |
| `chatplace.md` | `ChatPlace синк через chats_list а не automations_analytics.md` |
| `pricing.md` | `три тарифа от 35к до 250к рублей с рассрочкой.md` |
| `bugs.md` | `rate limit ChatPlace 500 запросов потом 429 на 5 минут.md` |
| `database.md` | `event_date ставится триггером из created_at автоматически.md` |

Следствия: файлов много, папки — грубая навигация, точная — по wiki-ссылкам.
Проверка имени: «это можно оспорить?» Если нет — это категория, переписать.

## Frontmatter и ссылки

```yaml
---
tags: [<project>/<topic>]
updated: 2026-11-02
status: active   # active | draft | deprecated
---
```

- `[[имя заметки]]` — внутри текста, как часть предложения, а не списком в конце.
- Обратные ссылки и Graph View бесплатны; AI использует ссылки как навигацию.
- Никогда не удалять: `status: deprecated` + ссылка на замену.
- Секретов, логов, полных DDL — нет: путь к файлу в backticks.

### Данные, у которых есть версия

Справочные таблицы предметной области (игровые формулы, лимиты API, тарифы) стареют
патчами и релизами. Держи версию в заметке — в frontmatter или первой строкой:
`patch: 1.1.12 (2026-09-22) · источник: <url>`. Достоверная, но непомеченная таблица
выглядит актуальной и врёт тихо; сверка `docs/` ↔ vault тогда идёт по `updated:` и `patch:`.

## Procedure

### A. Vault к действующему проекту

1. **Найди/создай vault и закрепи путь.** `OBSIDIAN_VAULT_PATH` в `$HERMES_HOME/.env`
   (абсолютный путь, Windows — прямой слэш). Не угадывай: нет пути — спроси.
   *Критерий:* `read_file` открывает `<vault>/00-home/index.md` или папка пуста.
2. **Проанализируй проект, а не фантазируй.** Читай: `README`, `HERMES.md`/`CLAUDE.md`,
   `docs/`, `db/`, точки входа, `git log --oneline -30`, конфиги зависимостей.
   *Критерий:* каждая созданная заметка ссылается на реальный файл/команду.
3. **Создай структуру** и наполни `atlas/` (архитектура, БД, деплой) — по одной заметке
   на тему, имена утверждениями. Старт: 15–20 заметок, не больше.
   *Критерий:* `python scripts/vault_check.py <vault>` → 0 битых ссылок.
4. **Добавь инструкцию про vault в правила проекта** (`CLAUDE.md` / `HERMES.md` /
   `.cursorrules`) — блок из раздела ниже, с реальным путём.
   *Критерий:* в файле правил есть путь к vault и три шага (старт/работа/финиш).
5. **Проверь и отчитайся**: число заметок, что осталось пустым (`inbox/`, `sessions/`).

### B. Новый проект с нуля

1. **Спецификация** — в обычном чате: цели, NFR числами, схема БД, API routes, правила.
   Она станет `docs/` и `atlas/`. (Каркас `docs/` — скилл `project-start`.)
2. **Проект** — `mkdir && git init`, правила в корень.
3. **Vault параллельно**, из спецификации, не из кода: `atlas/` = архитектура и данные,
   `knowledge/decisions/` = первые ADR с ценой, `00-home/index.md` = карта.
4. **Правило роста:** каждое решение/баг/паттерн по ходу разработки → заметка в тот же день.
   К 20+ файлам vault уже хранит историю «почему код такой».

### C. Ритуал сессии (повторяющийся)

| Момент | Действие |
|---|---|
| Старт | прочитать `00-home/index.md` + `текущие приоритеты.md`; если задача про модуль — заметку из `knowledge/` |
| Работа | по требованию контекста — `search_files` по vault, не перечитывать всё |
| Финиш («сохрани сессию») | 1) `sessions/YYYY-MM-DD-<тема>.md`: что делали, что сломалось, что осталось; 2) обновить `текущие приоритеты.md`; 3) решение → `knowledge/decisions/` (ADR с ценой); 4) баг → `knowledge/debugging/`; 5) новый паттерн → `knowledge/patterns/`; 6) новые заметки → ссылки в `index.md` |
| Раз в неделю | Graph View, разобрать `inbox/`, `index.md` под 100 строк |

Сессия без заметки — потерянный контекст. Заметка без ссылки в `index.md` — недостижимая.

## Блок для правил проекта

```markdown
## Obsidian Knowledge Vault
Хранилище знаний: <абсолютный путь>

### При старте сессии
Прочитай 00-home/index.md и текущие приоритеты.md.
Если задача касается модуля — прочитай заметку из knowledge/.

### При завершении (пользователь: "сохрани сессию")
1. Создай заметку в sessions/ с датой
2. Обнови текущие приоритеты.md
3. Если решение — создай в knowledge/decisions/
4. Если баг — создай в knowledge/debugging/
5. Обнови index.md если новые заметки
```

Имя файла правил по среде: Claude Code → `CLAUDE.md`, Hermes → `HERMES.md`,
Cursor → `.cursorrules`. Содержание одно и то же.

## Pitfalls

- **Категории вместо утверждений.** `auth.md` через месяц превращается в свалку из пяти тем;
  найти в ней ответ дороже, чем спросить заново.
- **`index.md` как свалка.** Оглавление >100 строк AI читает целиком и тратит контекст
  на навигацию. Детали — в заметки, в индексе — одна строка-ссылка.
- **Справочная таблица без версии.** Игровые формулы и внешние лимиты меняются патчами;
  таблица без `patch:` через полгода пересказывается как факт и уводит совет в сторону.
- **Vault-дубль `docs/`.** Если в заметке лежит полный DDL и он устарел — AI будет прав
  по заметке и неправ по коду. В заметке: путь к `db/schema.sql` в backticks.
- **Инструкция в правилах без пути к vault.** Без абсолютного пути AI не найдёт файлы и
  сделает вид, что прочитал. Путь — в правилах + `OBSIDIAN_VAULT_PATH`.
- **Ссылки на несуществующие заметки.** `[[...]]` с опечаткой = разрыв графа, Obsidian
  молчит. Проверяй `scripts/vault_check.py`.
- **Имя, которое перестало быть правдой.** Заметка вида `X не выдан.md` после починки продолжает
  утверждать обратное, а AI верит именам раньше текста — файл переименовывают в новое верное
  утверждение и правят все `[[ссылки]]` (индекс, модули, лог сессии) в том же изменении.
  Историю оставляют внутри: «было / стало / чем проверено», удалять заметку нельзя.
- **Массовая генерация «на будущее».** 200 заметок из воздуха не читаются и не проверяются.
  Расти на 2–5 заметок за сессию, каждая — из реального события.
- **Платный Obsidian / Sync / MCP «для галочки».** Vault — локальная папка `.md`;
  файлового доступа достаточно. Семантический поиск (MCP) оправдан на 100+ заметках.
- **MSYS-пути** (`/f/...`) в аргументах нативного python → «not found». Только `F:/...`.

## Verification

```bash
# структура, frontmatter, битые wiki-ссылки, размер индекса
terminal(command="python <skills>/note-taking/knowledge-vault/scripts/vault_check.py F:/path/to/vault")
```

Скрипт печатает: заметок, битых ссылок, заметок без frontmatter, заметок без ссылок,
строк в индексе. Exit 1 — есть битые ссылки или отсутствует индекс.

Готово, когда: 0 битых ссылок, у каждой заметки `tags/updated`, в правилах проекта есть
путь к vault, `sessions/` содержит заметку текущей сессии, а в отчёте назван остаток
(`inbox/` не разобран, `patterns/` пуст) — а не «всё готово».
