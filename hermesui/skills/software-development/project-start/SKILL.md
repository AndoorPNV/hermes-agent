# Project Start

Turn a project description into a working skeleton: `docs/` (спецификация → архитектура →
данные → API → модули → интеграции → план), `HERMES.md` с правилами, `project.yaml`,
опционально `db/schema.sql`, `modules/` и заметки Obsidian vault.

Скрипт создаёт **структуру с маркерами** `TODO(section)`, которые называют недостающий факт.
Заполнение — твоя работа: маркер либо заменяется фактом, либо файл помечается `status: draft`.
Без внешних зависимостей (stdlib Python).

**Когда принимают результат без маркеров** (кнопка «создать» в интерфейсе, готовый каркас для
пользователя), шаблоны не переписывай: сгенерируй и вычисти незаполненное — процедура и правила
проверки в скилле `scaffolded-project-docs`, раздел «Готовый каркас без заглушек».

## When to Use

- Пользователь даёт описание проекта и просит «создать начальную структуру / документацию /
  каркас» — до первой строки кода.
- Нужно зафиксировать договорённости (цели, границы, данные, интерфейсы) так, чтобы через
  месяц их можно было проверить, а не вспоминать.
- Нужен vault с архитектурой/модулями/интеграциями для долгой памяти проекта.

Не использовать для: добавления одной фичи в существующий проект; генерации бизнес-логики;
проектов, где документация уже есть и нужен только рефакторинг; vault-памяти для уже
существующего проекта без каркаса `docs/` — это `knowledge-vault`.

## Prerequisites

- `python` в PATH (stdlib достаточно; PyYAML **не** требуется).
- Скрипт: `$HERMES_HOME/skills/software-development/project-start/scripts/scaffold.py`
  (под Windows `$HERMES_HOME` = `%LOCALAPPDATA%\hermes`). Если путь иной — найди через
  `search_files(pattern='scaffold.py', target='files', path=<skills dir>)`.
- Проверка связности после заполнения: `scripts/check_links.py` того же скилла — относительные
  ссылки, `[[вики-ссылки]]` и frontmatter заметок (см. Verification).
- Vault (опционально): существующий каталог с `.obsidian/`; `OBSIDIAN_VAULT_PATH` в `.env`.

## How to Run

```
terminal(command="python \"$HERMES_HOME/skills/software-development/project-start/scripts/scaffold.py\" --root <abs> --name \"<Имя>\" --desc \"<одно предложение>\" --type <type> --stack \"<стек>\" --modules --vault <abs vault>")
```

Оболочка — bash (`$HERMES_HOME`), не cmd (`%HERMES_HOME%`); при сомнении передай путь
явно: `C:/Users/<user>/AppData/Local/hermes/skills/...`.

Windows: передавай **абсолютные** пути (`F:/...` или `C:/...`), не `/f/...` — нативные
программы не видят MSYS-пути. Кириллица в путях допустима.

## Quick Reference

| Флаг | Значение |
|---|---|
| `--root` | каталог проекта (создаётся) |
| `--name` | человеческое имя («CRM для сервиса») |
| `--desc` | одно предложение о продукте (попадает в README/HERMES/project.yaml) |
| `--type` | `hermes-extension` \| `web-app` \| `cli` \| `generic` |
| `--stack` | фактические версии: «FastAPI 0.115 + Postgres 16» |
| `--modules` | добавить `docs/05-MODULES.md` + `modules/` |
| `--no-db` / `--no-api` | не создавать `docs/03`+`db/schema.sql` / `docs/04` |
| `--vault` | абсолютный путь → заметки со связями; обычная папка, `.obsidian/` не нужен |
| `--force` | перезаписать существующие файлы (иначе `[skip]`) |
| `--dry-run` | показать план без записи |
| `--check` | посчитать оставшиеся `TODO(...)` (exit 1, если есть) |

Создаётся: `project.yaml`, `README.md`, `HERMES.md`, `.gitignore`, `.env.example`,
`docs/00…07`, `db/schema.sql`, `modules/README.md`, vault-заметки + `sessions/<дата>-старт проекта.md`
+ `inbox/` — 13 файлов без vault / 21 с `--vault`; с `--modules` — 15 / 23.

С `--vault` в `HERMES.md` попадает раздел **«Сессии и фиксация знаний»** (старт / работа /
6 шагов финиша / правило именования) — это единственное, что заставляет агента читать
vault на старте и писать заметку в конце. Без него vault существует, но не работает.

## Procedure

1. **Разбери описание на параметры.** Выпиши: имя, одно предложение сути, тип, стек,
   есть ли БД, есть ли внешние интерфейсы, нужны ли модули, есть ли vault.
   *Критерий:* все 8 параметров имеют значение или явный дефолт (`--no-db`, без vault).

2. **Спроси только то, что меняет структуру.** Максимум 3 вопроса одним `clarify`, и только
   если ответ добавляет/убирает файлы: (а) есть ли база данных, (б) нужны ли модули/плагины,
   (в) где vault. Всё остальное — решай сам и помечай `TODO`.
   *Критерий:* ни одного вопроса «какой стек вы предпочитаете» — стек берётся из описания.

3. **Запусти скрипт** (при существующей непустой папке — сначала `--dry-run`).
   *Критерий:* `записано: N`, в списке нет `[skip]` неожиданных файлов.

4. **Заполни `docs/` в порядке 01 → 02 → 03 → 04 → 05 → 06 → 07.**
   Спецификация до архитектуры: архитектура без целей — вкусовщина. Каждый раздел — по
   планке из `references/doc-rubric.md`.
   *Критерий:* у каждого FR есть «Приёмка:», у каждого NFR число, у каждого риска митигация.

5. **Заполни vault** (если создан): MOC «один взгляд», «Архитектура» (слои + 3 запрета),
   «Модули» (таблица), «Интеграции», «Данные и БД», ADR-001 с ценой.
   *Критерий:* из MOC до каждой заметки 1 переход; `TODO(one_glance)` закрыт.
   Vault как память AI (правило именования утверждениями, `sessions/`, `inbox/`, ритуал
   «сохрани сессию») — скилл `knowledge-vault`: он добавляет недостающие папки к этому MOC,
   а не заменяет его.

6. **Обнови `project.yaml`**: `stack` с версиями, `status: draft`.
   *Критерий:* в файле нет `TODO`.

7. **Проверь и отчитайся.**
   ```
   terminal(command="python <scaffold.py> --root <abs> --check")
   ```
   *Критерий:* `TODO-маркеров: 0` (или перечисли остаток, если пользователь просил **только**
   структуру — тогда честно скажи «каркас, N маркеров», не выдавай за готовую документацию).

8. **Создай Git-репозиторий только по просьбе.** Не делай `git init`/commit молча.

## Что писать в каждый файл

Планка по разделам — `references/doc-rubric.md`. Три правила, которые важнее остальных:

1. **Факт или маркер, ничего третьего.** «Примерно», «обычно», «современный» — не факт:
   либо число с источником-командой, либо `TODO`.
2. **Требование без приёмки — не требование.** Приёмка проверяется командой или наблюдением.
3. **Решение без цены — не решение.** В ADR обязателен раздел «Цена».

Шаблоны: `templates/adr.md`, `templates/module.yaml`.

## Pitfalls

- **Пустые заглушки.** Таблица из одних `TODO` выглядит как структура, но не несёт знания.
  Если факта нет — оставь маркер **и** напиши в отчёте, что осталось.
- **Выдуманные числа.** Версия, число эндпоинтов, размер БД — только из команды
  (`--version`, счётчик, `PRAGMA`). Нет команды — нет числа.
- **`--check` считает маркеры и внутри код-блоков, и внутри HTML-комментариев.** Шаблон
  каждого раздела несёт комментарий-инструкцию вида `<!-- TODO(section): … -->` с примером
  маркера: заполняя раздел, удаляй и комментарий целиком, иначе маркер остаётся «навсегда».
  Проверять до нуля, а не глазами.
- **Первая запись в непустую папку.** Без `--force` существующие файлы не трогаются, но
  и не сообщают об этом громко — смотри список `[skip]`.
- **Vault по угаданному пути.** Не создавай vault внутри чужого/системного каталога:
  только явный путь от пользователя или `OBSIDIAN_VAULT_PATH`.
- **Дублирование контрактов в заметках.** В vault — связи и «почему»; DDL и списки полей —
  только в `docs/`/`db/`. Иначе две правды разойдутся за неделю.
- **MSYS-пути** (`/f/...`) в аргументах нативного python → «not found». Только `F:/...`.
- **Символ `/` в имени заметки** (`Движок без I/O.md`) создаёт каталог вместо файла, и
  вики-ссылка на такую заметку не разрешается. В именах — «ввода-вывода», не «I/O».
- **Сгенерированные файлы не перезаписываются без полного чтения** (`write_file` требует
  свежего `read_file`; прочитанное через `terminal cat` guard не удовлетворяет). Быстрее не
  читать, а один раз удалить шаблоны (`rm docs/*.md README.md db/schema.sql "<vault>"/*.md`)
  и записать свои файлы: каркас к этому готов, структура разделов уже в голове.
- **Скилл может быть заблокирован политикой карты проекта** (`plugins/project-map-ui/policy.json`,
  у проекта пустой список `skills`). `skill_view` возвращает `BLOCKED: … Разрешены: —`.
  Разблокировка, а не обход: (а) id проекта — `sqlite3 projects.db "select id,name,primary_path from projects"`
  (файл в `$HERMES_HOME`), (б) бэкап `policy.json` рядом, (в) запись через сам модуль, чтобы
  формат совпал с ожидаемым: `python -c "import importlib.util,pathlib; spec=importlib.util.spec_from_file_location('p', pathlib.Path('policy.py').resolve()); m=importlib.util.module_from_spec(spec); spec.loader.exec_module(m); m.set_policy('project','<p_id>',{'skills':['project-start','knowledge-vault'],'toolsets':None,'mcp':None,'inherit':False})"`
  в каталоге плагина. Политика читается на каждый вызов — перезапуск не нужен. Назови правку
  в отчёте: это изменение конфигурации пользователя, а не деталь реализации.
- **Стек из головы.** Если проект про внешнюю систему (фреймворк, API), проверь версию
  через `web_search`/`web_extract` или в lock-файле, а не по памяти.
- **Описание без стека — не повод выдумывать.** Когда пользователь описывает задачу, а не
  инструменты, сними факты с машины: `which <tool>`, `ls "/c/Program Files"`, каталог
  установки, `python -c "import importlib.util as u; u.find_spec('lib')"`, конфиги приложения
  (`ls "$APPDATA/<vendor>"`, версия профилей) и `Get-Printer`/`find -iname "*.stl"` для
  устройств и артефактов. Ноль в выводе — тоже факт: «не установлено / не настроено» пишется
  как факт с командой, а не как `TODO`. Маркер оставляй только для того, чего в окружении
  физически нет (паспорт железа, инвентарь расходников), и перечисляй такие маркеры в отчёте
  последним блоком.
- **Каркас без ритуала.** Проект, созданный старой версией скрипта, имеет vault, но в
  `HERMES.md` нет раздела «Сессии» — агент никогда не прочитает MOC. Проверь:
  `search_files(pattern="Старт сессии", path=<root>/HERMES.md)`; нет — добавь блок из
  скилла `knowledge-vault`.
- **Двоеточие в `--desc` ломает YAML.** Скаляр вида «проект: делает X» без кавычек даёт
  `mapping values are not allowed in this context`; `project.yaml` нечитаем для машин.
  Скрипт квотирует `name`/`slug`/`description`/`stack`/`vault` через `json.dumps` — если
  каркас создан старой версией, добавь кавычки руками и проверь, что файл парсится.
- **Правило именования против сидов.** Созданные заметки (`Архитектура.md`, `Модули.md`)
  — категории, это нарушает правило «имя = утверждение». Они сиды: при первом реальном
  заполнении заметка переименовывается, ссылки из MOC правятся в том же изменении.
- **Один и тот же проект дважды.** Повторный запуск без `--force` безопасен (все `[skip]`),
  но `project.yaml.created` останется прежним — не «обновляй» дату ради аккуратности.

## Verification

```
# 1. структура на месте, маркеров нет
terminal(command="python <scaffold.py> --root <abs> --check")            # exit 0

# 2. ссылки в индексе разрешаются
search_files(pattern="\\]\\((\\./|\\.\\./)[^)]+\\)", target="content", path="<root>/docs")

# 3. README-команда запуска действительно работает (если проект уже кодовый)
#    — выполнить её, а не пересказать

# 4. vault связан: у каждой заметки есть tags/updated/status и хотя бы одна [[ссылка]]
search_files(pattern="^---$", target="content", path="<vault>", file_glob="*.md")

# 5. все относительные ссылки и [[вики-ссылки]] разрешаются, frontmatter на месте
terminal(command="python \"$HERMES_HOME/skills/software-development/project-start/scripts/check_links.py\" <root>")

# 6. DDL действительно применяется и держит ограничения — на пустой базе, а не «на глаз»
terminal(command="python -c \"import sqlite3;c=sqlite3.connect(':memory:');c.executescript(open('db/schema.sql',encoding='utf-8').read());print(c.execute('pragma integrity_check').fetchone()[0])\"")
```

Готово, когда: `--check` = 0, каждая цель в `01` имеет проверяемый признак, у каждого ADR
указана цена, MOC связывает все заметки, а в отчёте пользователю назван **остаток** работы
(если он есть), а не «всё сделано».
